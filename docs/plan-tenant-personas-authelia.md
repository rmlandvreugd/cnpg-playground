# Tenant Personas & Authelia Identity Model (local region)

Status: plan 2026-06-18. Source of truth for identity that the Capsule, Vault, Grafana,
ArgoCD, and SeaweedFS plans all reference.

Identity provider is **Authelia** (host container, replaced Dex). Group/user source of truth:
`authelia/config/users_database.yml`; OIDC clients in `authelia/config/configuration.yaml.tpl`;
secrets/hostnames in `scripts/common.sh`; rendered by `scripts/authelia-setup.sh`.

Tenant model: constructor = `rbr`, driver group = `ver`. Namespaces `rbr-ver-db` (database) and
`rbr-ver` (app). Future driver groups: `rbr-had`, etc.

**Topology note:** Vault and SeaweedFS are host Docker containers, not in-cluster services —
they have no Kubernetes Ingress/IngressRoute. They sit behind a separate edge Traefik
(`traefik-edge/`, static file config in `traefik-edge/dynamic/*.yaml`) on the host network,
distinct from the in-cluster Traefik that fronts ArgoCD/Grafana/gangplank. See
`plan-external-edge-traefik.md` for that topology.

## 1. Persona scoping (locked)

- **`*-db-admin` admins** stay as-is: `rbr-db-admin` (constructor admin), `rbr-ver-db-admin`
  (driver-group admin).
- **`rbr-ver-dev`** — developer, **per driver-group**. K8s `edit` in `rbr-ver` + `rbr-ver-db`,
  Vault `app`/`readonly` DB creds, Grafana **Editor**. Cannot touch other driver groups.
- **`rbr-po`** — product owner, **per constructor**. Read-only across **all** `rbr-*` driver
  groups: K8s `view` (`kubectl get`) via capsule-proxy, Grafana **Viewer**, **no DB write**.
- **`admin`** — global super-admin; member of every `<service>-admin` group.

Why dev is per-group but po is per-constructor: developers own one product/driver group and must
be isolated from siblings; a product owner needs a portfolio (read-only) view across the whole
constructor. This split drives the Capsule shape in `capsule-integration-plan.md` (one Tenant per
constructor; dev/group-admin scoped via per-namespace RoleBindings generated by Kyverno).

## 2. Persona × service access matrix

| User (email) | Authelia groups | K8s (Capsule/RBAC) | Vault DB role | Grafana | SeaweedFS |
|---|---|---|---|---|---|
| `admin@example.com` | all `*-admin` (incl. new `capsule-admin`, `argocd-admin`, `seaweedfs-admin`) | tenant owner everywhere | full | Admin (all orgs) | S3AdminRole (`s3:*`) |
| `rbr-admin@example.com` | `rbr-db-admin` | Tenant `rbr` owner (all `rbr-*` ns) | `rbr-db-admin` | `rbr` / Admin | S3BackupRWRole on `verstappen-backups` (`cnpg-playground-8ct`) |
| `rbr-ver-admin@example.com` | `rbr-ver-db-admin` | `admin` in `rbr-ver`+`rbr-ver-db` (RoleBinding) | `rbr-ver-db-admin` | `rbr` / Editor | S3BackupRWRole on `verstappen-backups` |
| `rbr-ver-dev@example.com` | `rbr-ver-dev` | `edit` in `rbr-ver`+`rbr-ver-db` (RoleBinding) | `app` / `readonly` | `rbr` / Editor | S3BackupRORole on `verstappen-backups` (`cnpg-playground-8ct`) |
| `rbr-po@example.com` | `rbr-po` | `view` across all `rbr-*` ns (Capsule additionalRoleBindings) | — | `rbr` / Viewer | S3BackupRORole on `verstappen-backups` |
| `unrelated@example.com` | — | forbidden | — | — | — |

SeaweedFS S3 buckets are backup-storage buckets (`loki`, `backups`, `verstappen-backups`), not
generic per-tenant buckets — there is no `rbr`/`rbr-ver` bucket namespace. `roleMapping` has no
`defaultRole`, so any group not listed above is denied. See `plan-seaweedfs-oidc.md` for the full
IAM config. Per `cnpg-playground-8ct`, `rbr-db-admin` (rbr-admin) now maps to `S3BackupRWRole` and
`rbr-ver-dev` to `S3BackupRORole`, both scoped to `verstappen-backups` (the two backup roles' trust
conditions accept a `oidc:groups` array so they cover the added groups alongside the originals).

## 3. Group catalog

Existing (keep): `admin`, `authelia-admin`, `grafana-admin`, `vault-admin`, `data-admin`,
`database-admin`, `k8s-admin`, `rbr-db-admin`, `rbr-ver-db-admin`.

New:

| Group | Purpose | Assigned to |
|---|---|---|
| `rbr-ver-dev` | driver-group developer | `rbr-ver-dev` user |
| `rbr-po` | constructor product owner (read-only) | `rbr-po` user |
| `capsule-admin` | Capsule tenant owner / cluster tenancy admin | `admin` |
| `argocd-admin` | ArgoCD `role:admin` | `admin` |
| `seaweedfs-admin` | SeaweedFS admin UI + S3 Admin policy | `admin` |

`<service>-admin` convention: each service maps **its own** admin group; `admin` holds them all so
one login administers everything. `k8s-admin` continues to cover Kyverno/cluster-scoped admin.

## 4. Authelia changes

`users_database.yml` — add users `rbr-ver-dev`, `rbr-po` (dev-default password hash, as existing
sample users); extend `admin` groups with `capsule-admin`, `argocd-admin`, `seaweedfs-admin`.

`configuration.yaml.tpl` — add OIDC clients (secrets seeded in `common.sh`, PBKDF2-hashed at render
like existing clients): `gangplank`, `argocd`, `seaweedfs-admin`, `seaweedfs-s3`. Redirect URIs to
the respective `*.<IP_DASHED>.sslip.io` hosts; scopes `openid email profile groups`.

Claims unchanged: `groups`, `email`, `preferred_username`, `name` via the default claims policy.

## 5. How each consumer reads identity

| Consumer | Mechanism | Mapping |
|---|---|---|
| kube-apiserver | structured `AuthenticationConfiguration` (Authelia issuer, audiences `kubernetes`+`gangplank`) | `email`→user, `groups`→groups |
| capsule-proxy | trusts apiserver OIDC; scopes visibility by `groups` | tenant owner/additionalRoleBindings |
| gangplank | OIDC → kubeconfig dispenser (edge-fronted at `gangplank.<IP>.sslip.io`, in-cluster Traefik) | `usernameClaim=email` |
| Vault | native OIDC auth method; UI is edge-fronted (`vault.<EDGE_IP>.sslip.io`, `traefik-edge`, host Docker container) with **no** forward-auth — Vault's own login page drives the OIDC flow | Authelia group → Vault policy |
| Grafana | generic OAuth, in-cluster Traefik. **Two instances:** the platform monitoring Grafana (`grafana.<IP>`, admin-only) and the per-tenant `grafana-rbr-ver.<IP>` (rbr personas) | server-admin via `role_attribute_path`; per-tenant roles via `org_mapping` (see note) |
| ArgoCD | OIDC (`argocd-cm`) + `argocd-rbac-cm`, in-cluster Traefik | `argocd-admin`→`role:admin` |
| SeaweedFS admin UI | **no native OIDC** (OSS `weed admin` has no OIDC code path) — edge-fronted (`seaweedfs-admin.<EDGE_IP>.sslip.io`, `traefik-edge`, host Docker container) behind an Authelia **forward-auth** middleware; `-adminUser`/`-adminPassword` remains as a behind-proxy backstop | `access_control`: `group:seaweedfs-admin`/`group:admin` only |
| SeaweedFS S3 API | real OIDC/STS (`-s3.iam.config`, `AssumeRoleWithWebIdentity`), edge-fronted (`seaweedfs.<EDGE_IP>.sslip.io`, `traefik-edge`) | `groups` → `roleMapping` (see §2 note); no `defaultRole`, so unmapped groups are denied |

`<EDGE_IP>` is the `traefik-edge` host (`172-18-0-250` locally), separate from the in-cluster
Traefik IP used by ArgoCD/Grafana/gangplank. Route definitions live in
`traefik-edge/dynamic/*.yaml`.

**Grafana OAuth note (verified live 2026-07-05, epic lhj):** three non-obvious Grafana
generic-OAuth facts, learned the hard way:
- `org_mapping` matches its group field against **`org_attribute_path`**, not
  `groups_attribute_path`. Both must be set to the `groups` claim or every entry silently
  misses and the user falls back to the default Viewer role.
- The **server-admin flag (`isGrafanaAdmin`) is derived from `role_attribute_path`**, *not* from
  a `GrafanaAdmin` role in `org_mapping`. An `org`-position `*` wildcard (`grafana-admin:*:GrafanaAdmin`)
  does **not** grant server admin. The admin persona gets it via
  `role_attribute_path: contains(groups, 'grafana-admin') && 'GrafanaAdmin' || ''` +
  `allow_assign_grafana_admin: true`. Empty-string fallback (with `role_attribute_strict: false`)
  lets non-admins fall through to `org_mapping`.
- The tenant Grafana (`grafana-rbr-ver`) has **only the default org (id 1)** — grafana-operator
  never creates a named "rbr" org, so `org_mapping` targets org `1`, not `rbr`. The instance
  *is* the rbr tenant, so the org name carries no meaning. The **platform** monitoring Grafana
  maps no tenant groups (admin persona only); tenant personas use `grafana-rbr-ver`.
