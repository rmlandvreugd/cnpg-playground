# Tenant Personas & Authelia Identity Model (local region)

Status: plan 2026-06-18. Source of truth for identity that the Capsule, Vault, Grafana,
ArgoCD, and SeaweedFS plans all reference.

Identity provider is **Authelia** (host container, replaced Dex). Group/user source of truth:
`authelia/config/users_database.yml`; OIDC clients in `authelia/config/configuration.yaml.tpl`;
secrets/hostnames in `scripts/common.sh`; rendered by `scripts/authelia-setup.sh`.

Tenant model: constructor = `rbr`, driver group = `ver`. Namespaces `rbr-ver-db` (database) and
`rbr-ver` (app). Future driver groups: `rbr-had`, etc.

---

## 1. Persona scoping (locked)

- **`*-db-admin` admins** stay as-is: `rbr-db-admin` (constructor admin), `rbr-ver-db-admin`
  (driver-group admin).
- **`rbr-ver-dev`** — developer, **per driver-group**. K8s `edit` in `rbr-ver` + `rbr-ver-db`,
  Vault `app`/`readonly` DB creds, Grafana **Editor**. Cannot touch other driver groups.
- **`rbr-po`** — product owner, **per constructor**. Read-only across **all** `rbr-*` driver
  groups: K8s `view` (`kubectl get`) via capsule-proxy, Grafana **Viewer**, **no DB write**.
- **`admin`** — global super-admin; member of every `<service>-admin` group.

Why dev is per-group but po is per-constructor: developers own one product/driver group and must
be isolated from siblings; a product owner needs a portfolio (read-only) view across the whole
constructor. This split drives the Capsule shape in `capsule-integration-plan.md` (one Tenant per
constructor; dev/group-admin scoped via per-namespace RoleBindings generated by Kyverno).

## 3. Group catalog

Existing (keep): `admin`, `authelia-admin`, `grafana-admin`, `vault-admin`, `data-admin`,
`database-admin`, `k8s-admin`, `rbr-db-admin`, `rbr-ver-db-admin`.

New:

| Group | Purpose | Assigned to |
|---|---|---|
| `rbr-ver-dev` | driver-group developer | `rbr-ver-dev` user |
| `rbr-po` | constructor product owner (read-only) | `rbr-po` user |
| `capsule-admin` | Capsule tenant owner / cluster tenancy admin | `admin` |
| `argocd-admin` | ArgoCD `role:admin` | `admin` |
| `seaweedfs-admin` | SeaweedFS admin UI + S3 Admin policy | `admin` |

`<service>-admin` convention: each service maps **its own** admin group; `admin` holds them all so
one login administers everything. `k8s-admin` continues to cover Kyverno/cluster-scoped admin.

---

## 4. Authelia changes

`users_database.yml` — add users `rbr-ver-dev`, `rbr-po` (dev-default password hash, as existing
sample users); extend `admin` groups with `capsule-admin`, `argocd-admin`, `seaweedfs-admin`.

`configuration.yaml.tpl` — add OIDC clients (secrets seeded in `common.sh`, PBKDF2-hashed at render
like existing clients): `gangplank`, `argocd`, `seaweedfs-admin`, `seaweedfs-s3`. Redirect URIs to
the respective `*.<IP_DASHED>.sslip.io` hosts; scopes `openid email profile groups`.

Claims unchanged: `groups`, `email`, `preferred_username`, `name` via the default claims policy.

---

## 5. How each consumer reads identity

| Consumer | Mechanism | Mapping |
|---|---|---|
| kube-apiserver | structured `AuthenticationConfiguration` (Authelia issuer, audiences `kubernetes`+`gangplank`) | `email`→user, `groups`→groups |
| capsule-proxy | trusts apiserver OIDC; scopes visibility by `groups` | tenant owner/additionalRoleBindings |
| gangplank | OIDC → kubeconfig dispenser | `usernameClaim=email` |
| Vault | OIDC + identity groups | Authelia group → Vault policy |
| Grafana | generic OAuth `org_mapping` | group → org/role |
| ArgoCD | OIDC (`argocd-cm`) + `argocd-rbac-cm` | `argocd-admin`→`role:admin` |
| SeaweedFS | admin-UI OIDC + S3 IAM STS (`AssumeRoleWithWebIdentity`) | `groups` → role/trust policy |

See: `capsule-integration-plan.md`, `plan-argocd-gitops.md`, `plan-seaweedfs-oidc.md`,
`plan-kyverno-policies.md`, `plan-self-service-dynamic-creds-pgadmin.md`.
