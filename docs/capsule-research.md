# Capsule Tenant Management: Research

Status: research planned 2026-05-04; **resolved + revised 2026-06-18**.
Scope: Capsule multi-tenancy in the self-service demo (local region).

> **Outcome:** all questions below are resolved in `capsule-integration-plan.md`. This doc is kept
> as the question/constraint record. **Identity is Authelia, not Dex** (the stack migrated); update
> any Dex mention you find here mentally to Authelia. capsule-proxy + gangplank, previously
> "optional/excluded", are now **in scope**.

## Why Capsule

The self-service design uses Vault policies (`rbr-db-admin`, `rbr-ver-db-admin`) and separate
namespaces (`rbr-ver-db`, `rbr-ver`) to isolate tenants. Capsule adds Kubernetes-native
multi-tenancy:

- `Tenant` CRD wraps namespace groups under owner subjects (Authelia `Group` claims).
- Admission webhook enforces RBAC, quotas, networking per tenant.
- Tenant users see only their namespaces via `kubectl` (with **capsule-proxy**).
- Complements Vault — Vault controls DB credential issuance; Capsule controls K8s API access.

Two access layers, one IdP (Authelia): K8s API (Capsule + apiserver OIDC + capsule-proxy) and DB
creds (Vault policies). See persona matrix in `plan-tenant-personas-authelia.md`.

## Existing stack (constraints)

- Runtime: rootless Podman + Kind.
- Networking: **Calico CNI** (Tigera operator) + MetalLB + Traefik v3 (`allowCrossNamespace: true`);
  Caretta/Radar for network observability.
- Auth: **Authelia** OIDC (host container; `groups` claim from `users_database.yml`).
- Secrets: ESO + Vault AppRole (`ClusterSecretStore vault-approle-rbr`).
- DB: CNPG (cluster-scoped), PostgreSQL 18 + pgaudit.
- Monitoring: kube-prometheus-stack + Grafana Operator, Loki/Mimir/Tempo/Alloy.
- Installed: cert-manager (Capsule dependency).
- NetworkPolicy: default-deny per tenant **generated by Kyverno** (not Capsule's deprecated generator).

Tenant model: constructor `rbr` = tenant; driver group `ver`; namespaces `rbr-ver-db` + `rbr-ver`;
future `rbr-had-db`, etc.

## Research areas (all resolved → see integration plan)

| ID | Question | Resolution (in `capsule-integration-plan.md`) |
|----|----------|-----------------------------------------------|
| R1 | Install + webhook conflicts (CNPG/ESO/Grafana Op/cert-manager) | OCI Helm chart in `capsule-system`; system SAs bypass `userGroups` scope → no deadlock. |
| R2 | Tenant model + owner subjects | `v1beta2`; **one Tenant per constructor** (`rbr`); owners = Authelia `Group` claims; `additionalRoleBindings` for read-only PO. |
| R3 | Cluster-scoped operator compatibility | Unaffected — operators run as their own SAs, not in `userGroups`. |
| R4 | Traefik + NetworkPolicy + capsule-proxy | Traefik CRDs pass ingress-class enforcement; NetworkPolicy via Kyverno; **capsule-proxy now in scope**. |
| R5 | Kind OIDC for group claims | Structured `AuthenticationConfiguration` (Authelia issuer; audiences `kubernetes`+`gangplank`, `MatchAny`). |
| R6 | System vs tenant namespaces | Automatic via `capsule.clastix.io/tenant` label; `protectedNamespaceRegex` guards system names. |
| R7 | Vault policy boundary | Two independent layers, common IdP (Authelia). |
| R8 | Teardown cascade | Tenant delete GCs namespaces; with ArgoCD, remove root Application first. |

## Decisions resolved before implementation

1. **Owner subject** = Authelia `Group` (`oidc:` prefix) — dynamic membership; requires apiserver
   OIDC via `AuthenticationConfiguration`.
2. **Hierarchy** = one `Tenant` per **constructor** (`rbr`), owning all driver-group namespace
   pairs. (Revised from the earlier per-driver-pair idea, to give `rbr-po` a portfolio view.)
3. **capsule-proxy + gangplank** = **included** (tenant kubectl + OIDC kubeconfig).
4. **NetworkPolicy** = default-deny generated by **Kyverno**, not Capsule.
5. **Phase placement** = Capsule install in `scripts/setup.sh` Phase 0; tenant CR reconciled by
   ArgoCD in Phase 1.
